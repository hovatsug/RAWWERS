# i18n and Multi-Language v1

## Locale selection rules

Effective locale resolution order:

1. Authenticated user preference (`user_locale_preference`) if set.
2. `Accept-Language` request header best match.
3. Default `en-GB`.

Supported locales in v1:

- `en-GB` (default)
- `pt-PT`
- `es-ES`
- `ru-RU`

## Namespaces and key conventions

Namespaces:

- `core`
- `errors`
- `notifications`
- `gamification`

Key patterns:

- Notifications: `notifications.<type>.subject|title|body`
- Gamification milestones: `gamification.milestones.<code>.name|description`
- Gamification seasons/cycles: `gamification.seasons.<code>.name`

Placeholders use Python style braces, for example: `Hello {name}`.

## Data model

- `user_locale_preference`: per-user locale preference.
- `i18n_bundle`: versioned bundle per `locale + namespace`.
- `i18n_key_audit`: key health (`present|missing|unused`).
- `localized_text`: localized overlays for user/admin-generated content entities.

## Translation rendering behavior

`app.services.i18n.t()` behavior:

1. Fetch active bundle for `locale + namespace` (cached in-process with TTL).
2. If missing key, fallback to `en-GB`.
3. If still missing, return key and write `missing` audit row.
4. Validate placeholders before formatting.

## Managing bundles

Admin endpoints:

- `GET /v1/admin/i18n/locales`
- `GET /v1/admin/i18n/bundles?locale=&namespace=`
- `POST /v1/admin/i18n/bundles`
- `POST /v1/admin/i18n/bundles/{id}/activate`
- `GET /v1/admin/i18n/missing-keys?locale=&namespace=`

Activation deactivates other versions for the same `locale + namespace` and invalidates cache.

All admin mutations are written to `admin_audit_log`.

## Client bundle consumption

Client-facing endpoint:

- `GET /v1/i18n/bundles?locale=pt-PT&namespace=core`

Response includes active `version` and `content` for offline bundle export (web/mobile).

## Adding a new language

1. Add locale to `SUPPORTED_LOCALES` in `app/services/i18n.py`.
2. Upload namespace bundles with incremented versions.
3. Activate bundle versions.
4. Run missing-key audit per namespace.
5. Validate notifications and gamification key coverage.

## Missing key detection flow

Use `GET /v1/admin/i18n/missing-keys` to compare locale bundle against `en-GB` in a namespace.

- Keys missing in locale => `missing`
- Keys only in locale and absent in `en-GB` => `unused`
- Key present in both => `present`

## UI client guidance (Next.js / Flutter)

- Fetch active bundles at startup and cache by `locale + namespace + version`.
- Do not translate API contract fields (ids, enum values, codes).
- Use localized text only for user-facing labels/messages.
- Keep analytics/logging in English keys and stable identifiers.
